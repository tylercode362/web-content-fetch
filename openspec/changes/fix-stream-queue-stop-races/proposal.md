# Why

下載來源串流錯誤可能逃出 HTTP Promise 邊界；佇列容量檢查與讀取 body 之間有競爭；小說發布期間的取消可能被後續 complete 覆寫。

# What Changes

- 使用 stream pipeline 接住來源錯誤並處理 client close。
- 在建立工作前再次同步核對容量。
- 發布後登錄輸出並重新檢查停止意圖，清理後再確認狀態。

# Impact

僅共用 HTTP／工作佇列邏輯與合成回歸。不接觸真實網站、憑證、既有工作或部署。

## 審查補充

- SSE 每個連線只保留一份待傳最新快照，背壓超過 15 秒即清理連線；同時最多 32 個訂閱者，超限明確回覆 503。重連仍取得完整快照。
- 漫畫與小說的最終清理後均再次核對停止意圖，避免取消或暫停被完成狀態覆蓋。
- 多檔發布每成功更名一個檔案即登錄工作輸出；後續更名失敗時保留已發布檔案的歸屬，讓既有明確取消／刪除流程可清理，不刪除其他工作檔案。

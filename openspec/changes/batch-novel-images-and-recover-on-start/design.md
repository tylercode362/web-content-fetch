For Linovel, WCF asks the existing secure chapter operation to include image retrieval. Chrome Bridge scrolls the chapter while rechecking the growing document height, extracts the lazy-loaded image URLs, then keeps that same background tab open while it fetches the verified image URLs. It sends image metadata once and transfers one bounded image at a time to WCF over the job-token-authenticated callback. WCF verifies the image URL against the registered chapter evidence, caps decoded bytes at 16 MiB, checks MIME and SHA-256, and durably checkpoints each image before acknowledging it. This avoids putting a whole chapter's binary payload into the 8 MiB secure WebSocket frame and avoids reopening the chapter for normal image retrieval.

If a same-tab image fetch fails, WCF falls back to the existing bounded `assets`/`asset` APIs for only the missing suffix. Those APIs retain the existing Linovel host allowlist, redirect, MIME, size, and digest checks. Existing manga batching remains unchanged.

On process startup, `loadJobs()` already changes interrupted `running` jobs to `queued`, and the existing startup drain resumes queued jobs from their checkpoints. A browser UI refresh only reloads persisted state; it does not resume a job whose status is `paused`, which remains available through the existing explicit resume action. The live OVERLORD job was observed as paused with `browser_command_timeout`, so refreshing its page is not expected to restart it.

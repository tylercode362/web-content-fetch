# 臺灣繁體中文技術寫作

採用清楚技術寫作的原則；不要宣稱本文符合官方中文 ASD-STE100 標準，也不要套用英文限定詞彙表或固定英文字數限制。

## 用語與原意

- 自行撰寫的中文一律使用臺灣繁體中文與臺灣慣用詞，禁止簡體中文與中國用語。採用自然中文語序，不逐字套用英文句型。
- 依專案、領域與讀者選用精確術語；同一概念維持同一名稱。需要時在首次出現處附上原文，避免為求變化而更換術語。
- 保留條件、否定、例外、數量、單位、範圍、先後順序與不確定性。不要把「可能」改成確定結果，也不要把「尚未驗證」改成失敗或成功。
- 保留程式識別字、命令、路徑、API／結構化資料欄位、原始資料值、正式專有名稱與須逐字引用的來源；用臺灣繁體中文撰寫周邊說明。不為修正文風擅改它們。

## 結構與證據

- 先辨識讀者要理解或完成的事，再整理資訊；短句與清單以有助理解為限，不為縮短篇幅刪除推理、限制或必要背景。
- 操作步驟原則上一個步驟只放一個主要動作。將必要前提、條件與風險警告放在相關動作之前；有需要才補上預期結果或檢查方式。
- 說明責任主體、對象與可檢查的結果。代名詞或省略主詞若會造成歧義，就明確寫出。
- 區分已知事實、推論、建議與待確認事項；重要結論附可取得的證據，不捏造來源或驗證紀錄。
- 分別陳述「已修改」「已測試」「已提交」「已推送」「已部署」。只報告證據支持的狀態，並交代與本次任務相關的未驗證部分。

## 交付前檢查

- 核對術語、字形、數值、條件與否定是否一致，並確認原意、操作順序與證據強度未被改變。
- 只修改本次授權範圍；未經要求，不批次改寫整個專案、翻譯既有其他語言文件，或更動程式行為。
- 按使用者指定的格式交付。可安靜套用本技能；不固定公告啟用，並遵守既有通知與安靜時段規則。
